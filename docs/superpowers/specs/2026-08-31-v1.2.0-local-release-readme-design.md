# V1.2.0 Local Release and README Design

**Status:** Approved for implementation on `main`  
**Date:** 2026-08-31  
**Repository:** `aiden493km/LingShu-TechJam2026-Robust-AIGC-Detector`

## Objective

Publish `v1.2.0` as the next judge-ready local WebDemo release with the latest
merged website, including the four-person About roster and approved portraits.
At the same time, reorganize the repository homepage README into a polished
large-open-source-project presentation without removing or weakening the current
experiment data, evaluation tables, evidence boundaries, deployment instructions,
team credits, or third-party notices.

## Release scope

The release continues the self-contained two-package contract established by
`v1.1.0`:

- `LingShu-WebDemo-Windows-x64-v1.2.0.zip`
- `LingShu-WebDemo-macOS-Apple-Silicon-v1.2.0.zip`

Each archive contains only the platform-appropriate one-click local WebDemo slice,
the frozen FP32 ONNX model, the latest committed production website, the selected
bundled runtime, platform quick-start material, the project MIT license, and the
applicable third-party notices. The normal GitHub tag source archives remain the
source distribution; the two release assets are not expanded into duplicate full
repository archives.

The release tag is lowercase `v1.2.0` to preserve the repository's existing tag
convention. The release title is `v1.2.0 — Portable WebDemo & README Refresh`.

## README direction

The approved visual direction is the product-and-research hybrid option.

The README header uses centered HTML-compatible Markdown with:

- the LingShu Intelligence and TikTok TechJam 2026 identity;
- the title `Robust AIGC Image Detector`;
- one evidence-bounded local-first robustness tagline;
- two compact rows of colorful badges for the current release, CI, Python,
  PyTorch, React, Vite, ONNX Runtime Web, WebGPU, WASM, offline operation,
  supported release platforms, TechJam, and MIT-licensed original project code;
- primary links to the `v1.2.0` local packages, the frozen checkpoint, WebDemo
  documentation, experiment results, and the Chinese data-pipeline report; and
- a first-screen metric strip containing only the already-recorded values:
  Mean Robust Accuracy `0.973977`, Worst-case Robust Accuracy `0.927090`, and
  External ROC-AUC `0.993124`.

The body gains a concise table of contents and improved section grouping, but
retains the existing problem statement, data-source boundary, validation ablation
matrix, held-out and external results, data-integrity audit, error-analysis caveat,
offline-deployment contract, frozen artifact hashes, CLI instructions,
reproduction guidance, limitations, team contributions, repository structure,
and TechJam identification. Existing claims may be clarified for release links or
license scope, but no metric, benchmark, or completion claim is promoted beyond
the committed evidence.

Badges must describe verifiable repository facts. A generic whole-repository MIT
badge is not used if it would imply that third-party models, datasets, codecs, or
upstream code were relicensed. The license badge is labeled as project code MIT.

## License boundary

A root `LICENSE` file carries the standard MIT License for original work created
by LingShu Intelligence contributors, including the later WebDemo source,
interface, release tooling, and original documentation, unless an individual file
states otherwise.

The README ends with a License section that makes the following boundary explicit:

- original LingShu project code and original documentation are MIT-licensed;
- Community Forensics and other retained upstream material continue under their
  original licenses;
- model weights, datasets, third-party browser packages, codecs, and bundled
  runtimes are not relicensed by the root MIT file; and
- redistribution must preserve `THIRD_PARTY_NOTICES.md`,
  `third_party/Community-Forensics-LICENSE`, and applicable dependency/runtime
  notices.

The two local archives include `LICENSE`, `THIRD_PARTY_NOTICES.md`, and the
Community Forensics license. Existing public-release review gates in the notices
remain visible; this release does not describe unresolved provenance or a complete
runtime-license bundle as legally cleared.

## Version and package contents

The WebDemo package metadata is aligned to `1.2.0` where the repository already
stores application version metadata. The production `web_demo/dist/` is rebuilt
from the merged source before packaging and must remain deterministic relative to
the committed distribution.

The v1.1.0 archives are inspected only as a structural reference. V1.2.0 is built
from the current approved `main` commit rather than by patching old release ZIPs.
Packaging excludes Git metadata, developer dependencies, generated test outputs,
runtime caches, secrets, and unrelated experiment assets.

## Verification

Before the release commit is tagged:

1. Run the repository Python test suite with the repository `.venv`.
2. Run the complete WebDemo Vitest suite.
3. Run TypeScript type checking.
4. Rebuild and verify the committed `web_demo/dist/` deterministically.
5. Run the repository portable-launcher checks that are available on Windows.
6. Build both ZIP files from the clean release commit.
7. Extract the Windows ZIP into a fresh path and run its documented `--check`
   entry point.
8. Inspect both archive manifests for path containment, platform-specific runtime
   selection, required model/site/license files, prohibited development files,
   and exact byte/hash consistency.
9. Verify macOS launcher line endings and executable ZIP attributes. The existing
   Apple Silicon CI validates the repository-side launcher contract; it is not
   represented as physical Finder, Gatekeeper, or headed-browser acceptance.
10. Compute SHA-256 for both final ZIP assets and publish the values in the GitHub
    Release body.

The tag is created only after the release commit is pushed and its current-head
GitHub checks pass. The annotated tag, release, and assets must all resolve to the
same release commit.

## Final state

Completion requires all of the following:

- local `main`, `origin/main`, and GitHub `refs/heads/main` match;
- annotated tag `v1.2.0` exists locally and remotely at the verified release
  commit;
- the GitHub Release is published, non-draft, non-prerelease, and contains exactly
  the two named platform ZIP assets;
- GitHub reports the uploaded asset digests matching the locally calculated
  SHA-256 values;
- the repository worktree is clean apart from the intentionally untracked visual
  brainstorming session, which is removed or ignored before final handoff; and
- unrelated Vercel and historical visual-design worktrees and artifacts are not
  modified or deleted.
